Branch `agent6/files6`. Rows for FEATURES.md: `docs/features-r6/files6.md`.

## Built

1. **Duplicate Downloads in Quick Sweep** (core `features/duplicates.rs` `DownloadDuplicates`, `sweep.rs`; UI `pages/sweep.rs`). Same matching as Duplicates on `~/Downloads` only, files changed in the last 3 months (mtime), downloads in progress (`.crdownload`, `.download` bundles, `.part`, `.partial`, `.opdownload`) never candidates, hard links once. One copy per set always kept (Smart keeper), the extra copies preselected; the tile shows their size and "N of M extra copies selected. One of each set stays." Review opens the Duplicates page on that exact plan. Run goes through the Duplicates feature's checks (`validate`, `validate_set`), so an edited plan selecting every copy moves nothing. Tile title via `sweep::tile_title`.
   **Developer Clutter tile**: `sweep::LATE_MODULES = ["dev_clutter"]`, looked up with `FeatureId::parse` at run time, so it appears once dev6's FeatureId and registry line are merged (no compile dependency). The tile shows the size found big and dev6's preselection small. Also `plan_page::blurb` and `can_stop` for it (by id string, as dev6 asked).
2. **Large & Old groups** (core `large_old.rs` `GroupBy`, `regroup`, `size_group`, `age_group`; UI `extras_files.rs` "Group by: Kind" pop-up). Size: 50 MB to 1 GB, 1 to 5 GB, over 5 GB, under 50 MB. Age by last opened: 3 to 6 months, 6 to 12 months, over a year, last 3 months, unknown (30-day months, 365-day year). Each group's checkbox is select all / none for that group; regrouping keeps the selection; choice remembered in `files.json`; nothing preselected. Each item's `modified` now holds the last-opened time (Spotlight last used, else atime/mtime), so "Sort by date" sorts by last opened too.
3. **Disk Map for the whole disk and external drives** (core `space.rs`, `features/space_lens.rs`; UI `pages/disk_map.rs`).
   - Picker "Where to look": Home folder, Startup Disk, each external volume "Name (capacity, free)". Volumes from `df -Pk` (all mounts: `/dev/disk*` under `/Volumes`, mount names with spaces handled; hidden, `com.apple.*`, Recovery/Preboot/VM/Update/xarts/iSCPreboot/Hardware left out; real folder, not a link) filtered by `diskutil list -plist external` when it answers (names from `VolumeName`). Storage bar shows the picked disk.
   - APFS approach: the walk of `/` crosses into the Data volume's device only (firmlinks `/Users`, `/Applications`, `/Library`, `/private/var`... live there) and skips `/System/Volumes` entirely (the Data volume's own mount point would count every firmlinked folder twice; Preboot, VM, Update are other volumes), `/Volumes` (other disks and the `Macintosh HD` link back to `/`), `/dev`, `/.Spotlight-V100`, `/.fseventsd`. Files counted once: hard links by (device, inode) on the first path in name order, symlinks never followed. External walks skip `.Spotlight-V100`, `.fseventsd`, `.Trashes`, `Backups.backupdb`. Skipped and unreadable space shows as "Not measured: X of the used space" (df used minus measured) for whole-disk locations.
   - Unreadable folders: `Node::unreadable`, `Tree::unreadable_paths`; list shows "Unknown" and "Could not be read. Full Disk Access may help."; summary "Could not be read: N folders". Never a silent 0.
   - Allow-list: home folder (minus protected, Library, hidden, apps) plus, on mounted external volumes, what is inside their top user folders (`space::volume_user_folders`: real folders, not hidden, not the volume's system folders, not apps). Never `/`, `/Volumes` or a volume itself (safety6 R3). Locked with reasons: "Part of macOS" (System, Library, usr, bin, sbin, private, etc, var, tmp, dev, cores, Volumes), "Outside your home folder", "System data of this disk: ..." (`.Spotlight-V100`, `.Trashes`, `.fseventsd`, `Backups.backupdb`, `.DocumentRevisions-V100`, `.TemporaryItems`), "Hidden system data of this disk", "A top folder of this disk (open it...)". `SpaceLens::validate` refuses locked items of an edited plan item by item; the executor's allow-list refuses the rest; an unplugged volume leaves the allow-list. External items move to that volume's `.Trashes/<uid>` with Undo.
   - Snapshots (agreed with health6 on the board): `space_snapshots.rs` (new), `<data>/disk-map-snapshots.json` version 1, two newest per location (`home`, `startup`, `volume:<name>`, `folder:<path>`), entries 2 levels deep, 300 biggest; `saved`, `latest_pair`, `growth`. Written in the measuring job when not stopped. (health6 also watches `disk_map.tree()` for its own summary; `State::tree()` unchanged.)
4. **APFS clones**: not reliably detectable through command-line tools. `stat -f %b` (allocated blocks) reports the full allocation for each clone, so allocated vs logical says nothing; `ls -lO`, `mdls`, `diskutil` show no clone data. Only `getattrlist` with `ATTR_CMNEXT_CLONEID` / `ATTR_CMNEXT_EXT_FLAGS` (`EF_SHARES_ALL_BLOCKS`, macOS 10.15+) knows, which needs a system call (FFI) this crate does not make (no unsafe code, no macOS cfg code). Documented in `duplicates.rs`; clones are listed as copies; MAC-CHECK.
